# แดชบอร์ดประมาณการเงินทุน BoromTech

เว็บส่วนตัวสำหรับผู้บริหารที่ได้รับเชิญ ใช้ดูประมาณการเงินสด แก้ตัวเลขบนเว็บ และบันทึกรายจ่ายจริงพร้อมหลักฐาน เข้าสู่ระบบด้วย Google ได้เฉพาะอีเมลที่อยู่ในรายชื่ออนุญาต

รีโปนี้เป็นรีโปสาธารณะ จึงเก็บเฉพาะข้อมูลตัวอย่าง ห้ามใส่ตัวเลขจริง ชื่อจริง อีเมลจริง หรือความลับใดๆ ลงใน git

## ข้อมูลในรีโปนี้เป็นตัวอย่าง

ไฟล์ `data/forecast.example.json` เป็นตัวเลขกลมสมมติ และมีข้อความ `ตัวอย่างข้อมูล / Example data, not real figures` ใช้ตรวจสคีมาและเป็นต้นแบบตอนนำเข้าครั้งแรกเท่านั้น แอปที่รันอยู่ไม่ได้อ่านไฟล์นี้

## ข้อมูลอยู่ที่ Supabase

หลังตั้งค่าแล้ว ตัวเลขทั้งหมดอยู่ใน Postgres ของ Supabase ไม่ได้อยู่ในไฟล์ลับบน Render และไม่ต้อง redeploy เมื่อแก้ตัวเลข เปิดหน้าใหม่จะเห็นค่าล่าสุด

เก็บไว้ในฐานข้อมูล:

- การตั้งค่า: ชื่อบริษัท สกุลเงิน ทุนจดทะเบียน ทุนยกมา (จำนวนและสัดส่วน %) อัตราแลกเปลี่ยนพร้อมแหล่งที่มาและวันที่ และข้อความสูตรยอดคงเหลือ
- เดือน และรายรับของแต่ละเดือน
- รายจ่ายประมาณการ: ชื่อ กลุ่ม เดือน จำนวนเงิน เครื่องหมายสมมติ หมายเหตุ
- สมมติฐาน และรายการที่ยังไม่รวม
- รายจ่ายจริง: วันที่ รายการ ประเภท ผู้รับเงิน ระยะเวลา จำนวนเงิน ภาษีหรือสกุลต่างประเทศ ผู้ทดรองจ่าย วิธีจ่าย เลขที่ใบเสร็จ ชื่อบนใบเสร็จ การโอนสิทธิ์ หมายเหตุ และไฟล์หลักฐาน
- คำนำหน้าเลขที่เอกสาร ค่าเริ่มต้นคือ `EXP` จึงได้เลขอย่าง `EXP-0001` เปลี่ยนเป็น `PRE` ได้ในหน้า Capital ถ้าต้องการให้ตรงคำว่า PRE บนแม่แบบใบทดรองจ่าย

จำนวนเงินเป็นเลขทศนิยมพอดี ไม่เกิน 2 ตำแหน่ง อัตราแลกเปลี่ยนเก็บทศนิยมได้มากกว่านั้น เช่น `33.78705` เชิงอรรถบนแดชบอร์ดแสดงอัตราตามสตริงที่บันทึกไว้ ไม่ปัดเป็นสองตำแหน่ง

ทุกตารางเปิด Row Level Security และไม่ได้สร้างนโยบายให้บทบาท `anon` หรือ `authenticated` เว็บไม่ได้คุยกับ Supabase จากเบราว์เซอร์ เซิร์ฟเวอร์ใช้ `SUPABASE_URL` กับ `SUPABASE_SERVICE_ROLE_KEY` เท่านั้น ไฟล์หลักฐานอยู่ในถังส่วนตัวชื่อ `receipts` เซิร์ฟเวอร์สร้างลิงก์อายุสั้นเพื่อดึงไฟล์ แล้วส่งไฟล์ให้เบราว์เซอร์เอง

ถ้ายังไม่ได้ตั้งตัวแปร Supabase สองตัว ผู้ที่ล็อกอินแล้วจะเห็นข้อความว่า Supabase is not configured และ `/health` ยังตอบ 200

## สคีมาสำหรับนำเข้าครั้งเดียว

จำนวนเงินในไฟล์ JSON เป็นสตริงทศนิยม ไม่เกินสองตำแหน่ง เช่น `"1500.50"` อัตราแลกเปลี่ยนเป็นสตริงและมีทศนิยมได้ถึง 8 ตำแหน่ง `updatedAt` เป็นวันที่ `YYYY-MM-DD` หรือวันเวลา ISO เช่น `2026-01-01T07:02:00+07:00` ระบบเก็บเฉพาะวันที่

| คีย์ | ความหมาย |
| --- | --- |
| `company` | ชื่อบริษัท |
| `currency` | สกุลเงิน เช่น `THB` |
| `registeredCapital` | ทุนจดทะเบียน ไม่ถูกบวกเข้ายอดเงินสด |
| `openingCapital` | `amount`, `sharePercent`, `assumed`, `label`, `timing` |
| `fx` | `base`, `quote`, `rate`, `source`, `updatedAt`, `updatedDisplay` |
| `balanceFormula` | ประโยคสูตรยอดคงเหลือ |
| `months` | รายเดือน แต่ละเดือนมี `key`, `label`, `labelFull`, `revenue`, `items` |
| `assumptions` | ข้อความสมมติฐาน |
| `notYetIncluded` | รายการที่ยังไม่ใส่ในตัวเลข |

แต่ละรายการใน `items` มี `group`, `groupName`, `name`, `amount`, `assumed` และ `note` ได้ถ้าต้องการ

`usd` (ไม่บังคับ) เป็นสตริงทศนิยมไม่เกินสองตำแหน่ง เช่น `"12.00"` ใช้แสดงยอดดอลลาร์คู่กับยอดบาทบนแดชบอร์ดและหน้า Expenses › Planned ยอดรวมและยอดคงเหลือคำนวณจาก `amount` (บาท) เท่านั้น

`fx` ยังอยู่ในไฟล์และในฐานข้อมูล เพื่อให้คำสั่งนำเข้าตรงกับคอลัมน์เดิม หน้าเว็บไม่แสดงและไม่ให้แก้ค่านี้แล้ว อัตราของรายจ่ายจริงกรอกทีละรายการในหน้าบันทึกรายจ่าย

ยอดสิ้นเดือน = ยอดก่อนหน้า + รายรับ − ผลรวมรายจ่าย เดือนแรกใช้ทุนยกมาเป็นยอดก่อนหน้า

ตรวจไฟล์ก่อนนำเข้า:

```bash
node scripts/check-forecast.js /path/outside/the/repo/forecast.json
```

## ตัวแปรที่ต้องตั้ง

| ชื่อ | จำเป็น | ค่า |
| --- | --- | --- |
| `GOOGLE_CLIENT_ID` | ใช่ | Client ID ของ OAuth |
| `GOOGLE_CLIENT_SECRET` | ใช่ | Client secret ของ OAuth |
| `SESSION_SECRET` | ใช่ | ค่าสุ่มยาวสำหรับเซ็นคุกกี้ เช่นผลของ `openssl rand -base64 32` |
| `ALLOWED_EMAILS` | ใช่ | อีเมลที่อนุญาต คั่นด้วยจุลภาค ใช้โดเมนตัวอย่างเช่น `person.one@example.com` |
| `SUPABASE_URL` | ใช่ ถ้าจะเห็นข้อมูล | Project URL จาก Supabase ต้องขึ้นต้นด้วย `https://` |
| `SUPABASE_SERVICE_ROLE_KEY` | ใช่ ถ้าจะเห็นข้อมูล | กุญแจ `service_role` ใช้บนเซิร์ฟเวอร์เท่านั้น ห้ามใช้ anon key |
| `BASE_URL` | ไม่ | URL ภายนอกของแอป ไม่ต้องมี `/` ท้าย ถ้าไม่ใส่ จะใช้ `RENDER_EXTERNAL_URL` |
| `NODE_ENV` | ไม่ | Blueprint ตั้งเป็น `production` เพื่อให้คุกกี้เป็น Secure |
| `PORT` | ไม่ | Render ตั้งให้เอง |

ถ้าตัวแปร Google หรือเซสชันว่าง แอปตอบ `503` และไม่เปิดข้อมูล `GET /health` เป็นข้อยกเว้น: ตอบ `200` พร้อม `{ "ok": true }` เสมอ เพื่อให้ health check ของ Render ผ่านก่อนตั้งค่า OAuth และไม่ส่งสถานะการตั้งค่าออกไป ถ้าขาดเฉพาะ Supabase แอปยังเปิดได้ และหน้าหลังล็อกอินบอกว่า Supabase is not configured

## ตั้งค่า (เจ้าของระบบ)

### 1. Google Cloud Console

1. สร้างโปรเจกต์ใหม่ หรือเลือกโปรเจกต์ที่ใช้กับแอปนี้
2. ไปที่ APIs & Services แล้วเปิด OAuth consent screen
3. เลือก User type เป็น **External**
4. ใส่ชื่อแอปและอีเมลผู้ติดต่อ ขอบเขต (scopes) ให้มีแค่ `openid`, `email` และ `profile` ห้ามขอขอบเขตอื่น
5. **Publish** consent screen ถ้ายังเป็น Testing จะมีแค่ test users ที่เข้าได้
6. สร้าง Credentials → OAuth client ID ชนิด **Web application**
7. ใส่ Authorized redirect URI ให้ตรงทุกตัวอักษร:

   `https://<ชื่อแอป>.onrender.com/auth/google/callback`

   ถ้าจะลองบนเครื่องตัวเอง ให้เพิ่ม `http://localhost:3000/auth/google/callback` อีกหนึ่งรายการ
8. คัดลอก Client ID และ Client secret ไปใส่ใน Render ห้าม commit ค่าสองอย่างนี้

### 2. Supabase

1. เปิด [supabase.com](https://supabase.com) แล้วสร้างโปรเจกต์ใหม่ แผนฟรีใช้ได้ ตั้งรหัสผ่านฐานข้อมูลแล้วเก็บไว้นอก git
2. รอจนโปรเจกต์พร้อม แล้วเปิด **SQL Editor**
3. เปิดไฟล์ `supabase/migrations/20261028120000_init.sql` จากรีโปนี้ คัดลอกทั้งหมด วางในช่อง SQL แล้วกด **Run**
   แล้วทำซ้ำกับไฟล์ `supabase/migrations/20261028150000_forecast_item_usd.sql` (เพิ่มคอลัมน์ `usd` ให้รายจ่ายประมาณการ) ถ้าเคยรันไฟล์ init ไปแล้ว ให้รันเฉพาะไฟล์นี้ รันซ้ำได้ ต้องรันก่อน deploy โค้ดเวอร์ชันนี้
4. ถ้ามีข้อความเตือนเรื่องถัง `receipts` ให้สร้างเอง: ไปที่ **Storage → New bucket** ตั้งชื่อ `receipts` ปิด **Public bucket** จำกัดชนิดไฟล์เป็น PDF, JPEG, PNG และขนาด 5 MB ถ้าหน้าเว็บมีช่องนั้น
5. อย่ากดเพิ่ม Policy ทั้งในตารางและใน Storage ถังต้องเป็นส่วนตัว
6. เปิด **Project Settings → API**
7. คัดลอก **Project URL** ไปเป็น `SUPABASE_URL`
8. คัดลอกกุญแจ **service_role** ไปเป็น `SUPABASE_SERVICE_ROLE_KEY` นี่คือความลับของเซิร์ฟเวอร์ ห้ามใส่ในหน้าเว็บ ห้ามส่งให้เบราว์เซอร์ และห้าม commit

### 3. Render

1. ใน GitHub ให้สิทธิ์แอปของ Render เฉพาะรีโปนี้ ไม่ต้องเปิดทั้งองค์กร
2. ใน Render เลือก **New → Blueprint**
3. เลือกรีโปนี้ และสาขา **main** ไฟล์ `render.yaml` จะสร้าง Web Service แพลนฟรี และ auto-deploy เฉพาะเมื่อมี commit บน `main`
4. เติม `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SESSION_SECRET`, `ALLOWED_EMAILS`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` ช่องเหล่านี้เป็น `sync: false` จึงไม่มีค่าอยู่ใน git
5. `BASE_URL` ใส่ `https://<ชื่อแอป>.onrender.com` ได้ ถ้ายังไม่รู้ชื่อ ให้เว้นว่าง แอปจะใช้ `RENDER_EXTERNAL_URL`
6. ไม่ต้องเพิ่ม Secret File ไม่มีไฟล์ประมาณการบน Render

แพลนฟรีของ Render จะหลับหลังไม่มีคนเปิดประมาณ 15 นาที ครั้งถัดไปอาจใช้เวลาครู่หนึ่งกว่าจะตื่น ข้อมูลไม่หายเพราะอยู่ใน Supabase

### 4. นำเข้าตัวเลขปัจจุบันครั้งเดียว

ทำบนเครื่องตัวเองหลังใส่ตัวแปรในไฟล์ `.env` แล้ว วางไฟล์ JSON จริงไว้นอกรีโป เช่นในโฟลเดอร์บ้าน ห้ามวางในรีโป และห้ามชี้คำสั่งไปที่ไฟล์ในรีโป สคริปต์จะปฏิเสธ

```bash
npm install
npm run import-forecast -- /full/path/outside/the/repo/forecast.json
```

คำสั่งนี้แทนที่การตั้งค่า เดือน รายรับ รายจ่ายประมาณการ สมมติฐาน และรายการที่ยังไม่รวม ไม่ลบรายจ่ายจริงที่บันทึกบนเว็บแล้ว รันซ้ำได้ถ้าต้องการนำเข้าใหม่

หลังนำเข้า เปิดเว็บแล้วรีเฟรช จะเห็นตัวเลขโดยไม่ต้อง deploy ใหม่ ต่อจากนั้นแก้บนเว็บได้ หน้าเว็บมีสองภาษา กดปุ่ม **EN | TH** ที่มุมขวาบนเพื่อสลับ (ค่าเริ่มต้นเป็นภาษาอังกฤษ ระบบจำภาษาที่เลือกไว้ในคุกกี้ `bt_lang`) มี 4 แท็บ:

- **Dashboard** ภาพรวม
- **Income** รายรับรายเดือน และเพิ่มหรือลบเดือน (เลือกเดือนจากปฏิทิน ระบบตั้งชื่อเดือนเป็นภาษาอังกฤษให้)
- **Expenses** มีสองมุมมอง: **Actual** รายจ่ายจริงพร้อมหลักฐานและปุ่มพิมพ์ใบทดรองจ่าย (ใบพิมพ์ยังเป็นภาษาไทย) และ **Planned** รายจ่ายประมาณการ
- **Capital** ทุนจดทะเบียน ทุนยกมา อัตราแลกเปลี่ยนที่กรอกเอง และข้อมูลบริษัท สัดส่วนทุนยกมาคำนวณให้อัตโนมัติ

ลิงก์เก่า `/settings` และ `/reimburse` พาไปหน้า Capital และ Expenses ให้เอง

### 5. เพิ่มหรือลบอีเมล

1. เปิดบริการบน Render แล้วไปที่ Environment
2. แก้ `ALLOWED_EMAILS` เป็นรายการอีเมลคั่นด้วยจุลภาค เช่น `person.one@example.com, person.two@example.com`
3. ช่องว่างหัวท้ายและตัวพิมพ์ใหญ่เล็กไม่มีผล
4. กดบันทึก Render จะรีสตาร์ทบริการ
5. อีเมลที่เพิ่มต้องเข้าสู่ระบบใหม่ อีเมลที่เอาออกจะใช้ของเดิมไม่ได้ทันที เพราะทุกคำขอตรวจรายชื่ออีกครั้ง คุกกี้เซสชันมีอายุ 7 วัน

ใช้เฉพาะอีเมลที่ Google ยืนยันแล้ว (`email_verified` เป็นจริง)

## ใช้บนเว็บ

หลังล็อกอินมีเมนูแดชบอร์ด ตั้งค่า ประมาณการ รายจ่ายจริง และทดรองจ่าย

- แดชบอร์ดยังเป็นกราฟสามแท่ง ตารางรายเดือนที่ขยายได้ ยอดรวมรายรายการ และเชิงอรรถอัตราแลกเปลี่ยนกับสมมติฐาน อ่านจาก Supabase ทุกครั้งที่เปิดหน้า
- ตั้งค่าแก้ชื่อบริษัท ทุน อัตราแลกเปลี่ยน สูตร หมายเหตุ และคำนำหน้าเลขเอกสาร
- ประมาณการเพิ่มเดือน แก้รายรับ และเพิ่ม แก้ หรือลบรายจ่ายที่วางแผนไว้
- รายจ่ายจริงบันทึกวันที่ รายการ ประเภท ผู้รับเงิน ระยะเวลา จำนวนเงิน ภาษีหรือเงินต่างประเทศ ผู้ทดรองจ่าย วิธีจ่าย เลขที่ใบเสร็จ ชื่อบนใบเสร็จ และการโอนสิทธิ์ พร้อมไฟล์ PDF, JPG หรือ PNG ไม่เกิน 4 ไฟล์ ไฟล์ละ 5 MB
- ใบทดรองจ่ายพิมพ์ได้หนึ่งใบต่อหนึ่งรายจ่ายจริง ตามโครงแม่แบบก่อนจัดตั้งบริษัท เป็นแบบร่าง มีป้าย TEMPLATE DRAFT ส่วนที่ 1 ถึง 3 และข้อความปกปิดเลขบัญชี ใช้ปุ่มพิมพ์ของเบราว์เซอร์เพื่อบันทึก PDF

ทุกคำขอที่แก้ไขข้อมูลต้องมีเซสชันของอีเมลในรายชื่อ และโทเคนยืนยันในฟอร์ม ผู้ที่ยังไม่ล็อกอินถูกส่งไปหน้าเข้าสู่ระบบ ส่วน API ตอบ 401

## รันบนเครื่อง

```bash
npm install
npm test
npm run check
```

สร้างไฟล์ `.env` จาก `.env.example` แล้วเติมค่าจาก Google และ Supabase จากนั้น:

```bash
npm run dev
```

เปิด `http://localhost:3000` ถ้ายังไม่ใส่ตัวแปร Supabase หลังล็อกอินจะเห็นข้อความว่ายังไม่ได้ตั้งค่า

เส้นทางที่เปิดได้โดยไม่ต้องล็อกอินมีแค่หน้าเข้าสู่ระบบ, ไฟล์หน้าตาของหน้านั้น (`/login-assets/`), จุดเริ่ม Google (`/auth/google`), callback, หน้ายืนยันออกจากระบบ, และ `/health` ข้อมูลอยู่ที่ `/` และ `/api/forecast` ซึ่งต้องมีเซสชัน
